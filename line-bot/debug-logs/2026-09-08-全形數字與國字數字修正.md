# 小蜜（LINE 機器人）除錯記錄：全形數字／國字數字對不到規則

> 來源：另一個對話視窗的除錯過程，2026-09-08 備份存檔。
> 這份是完整過程記錄（含 debug 細節），濃縮版已寫入 [CHANGELOG.md](../CHANGELOG.md)。

## 問題 1：全形數字打不通

**現象**：使用者打「第3則網址」，若是用注音／中文鍵盤輸入數字，Mac 有時會自動打成全形數字（３）而不是半形（3）。JavaScript 的 `\d` 正規表示式只認半形數字，全形的３對不到任何規則，整句話掉進閒聊層，AI 開始亂編內容（幻覺）。

**影響範圍**：全部靠數字比對的功能——刪除行程幾號、法規選號、第幾則網址等等，只要規則沒接住就會被閒聊層接手瞎編。

**根因**：規則層（非 AI）本身沒有處理全形→半形轉換，不是 AI 判斷錯誤。

**修法**：收到文字訊息時，先統一把全形數字轉成半形，再進行後續所有判斷（單一入口修正，一次修掉所有靠數字判斷的功能）。

**執行過程**：
- 讀取並編輯 `code.gs`，執行 2 個指令驗證（+2 / -1 行變動）
- 確認修正生效
- 更新 `CHANGELOG.md`（+1 行）
- Commit message：「修正全形數字（中文鍵盤常見）對不到規則的問題，影響第X則網址/刪除行程/法規選號等所有數字功能」

**驗收提示**：貼上重新部署後，重新測「第3則網址」應正常回連結，不再掉進閒聊瞎編。

## 問題 2：國字數字（「第三則網址」）打不通

**使用者提問**：國字可以嗎？

**回答**：當時還不行。「第三則網址」這種國字數字對不到規則（正規表示式只認阿拉伯數字），會跟全形數字一樣的問題，掉進閒聊。

**評估**：可以加一個小工具，把「一～九十九」這種國字轉成阿拉伯數字（零 AI、純規則轉換，不會有幻覺風險），套用到以下四個看數字的地方：
1. 「第X則網址」
2. 「刪除第N筆」
3. 「法規總表」選號碼
4. 已選定法規時的「第X條」

**執行過程**：
- 新增國字→阿拉伯數字轉換工具（`chineseNumToArabic()`，純規則，零 AI），執行指令驗證（+22 / -0 行）
- 更新四個觸發點以支援國字輸入（+11 / -10 行）
- 全部轉換結果驗證正確
- 更新 `CHANGELOG.md`（+1 行）
- Commit message：「新增國字數字支援（一~九十九），套用到第X則網址/刪除第N筆/法規選號/第X條」

**驗收提示**：貼上重新部署後，「第三則網址」「刪除第三筆」「法規總表選十二」這類國字輸入都能用。

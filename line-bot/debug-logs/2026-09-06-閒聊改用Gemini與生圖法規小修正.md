# 小蜜（LINE 機器人）除錯記錄：Mistral 429、生圖觸發、法規反查關鍵字

> 來源：本次對話視窗，2026-09-08 備份存檔。
> 這份是完整過程記錄（含 debug 細節），濃縮版已寫入 [CHANGELOG.md](../CHANGELOG.md)。

## 問題 1：閒聊功能持續回「我這邊有點恍神」

**現象**：閒聊功能開始持續回「😏 我這邊有點恍神，你再說一次？」，一開始不確定根因。

**除錯方式**：先在 `chatWithPersona` 的 `catch` 區塊加上除錯訊息，把 `callMistralJSON` 拋出的真實例外顯示到 LINE 上（延續本對話一貫方法：先用真實錯誤訊息驗證，不用猜的）。

**根因**：使用者實測後回報錯誤訊息為 `Exception: https://api.mistral.ai/ ... 錯誤:429 ... "message":"Rate limit exceeded"`，確認是 Mistral API 免費方案的頻率限制，不是模型下架。

**修法（分兩階段）**：
1. 先只把 `chatWithPersona` 改用新寫的 `callGeminiJSON`（因為 Gemini key 已經儲值開通付費額度），移除除錯訊息
2. 使用者接著問「是不是全部都改用Gemini比較好」，討論利弊後（好處：只剩一把key好管理；壞處：全部功能集中同一把key，若Gemini自己撞到額度限制會一次全掛）決定全面移除 Mistral 依賴，把 `queryLawTopic`、`queryLaw`、`summarizeYouTube`、`summarizeWebpage` 全部改呼叫 Gemini，`callGeminiText` 補上可調 temperature 參數，刪除 `callMistralText`／`callMistralJSON`／`_RAW_MISTRAL_KEY`

**驗收**：貼上重新部署，測閒聊訊息確認不再出現恍神訊息。

## 問題 2：AI 曾編造「某餐廳打電話來問訂位」這種根本沒發生過的聯絡事件

**現象**：使用者截圖顯示，AI 在閒聊中編造「林聰明火鍋店打電話來問要不要訂位」，但這件事根本沒發生過——屬於過去人設規則沒涵蓋到的幻覺類型（先前已防範編造職業/行程/法條，但沒明講不能編造聯絡事件）。

**修法**：在 `SECRETARY_PERSONA` 人設規則明講：不能編造「有人/有店家/有誰打電話或傳訊息聯絡過使用者」這種事件，合法資訊來源只有(a)使用者這次對話親口說的、(b)長期記憶裡真的有記載的，其餘一律「不知道就是不知道」。

## 問題 3：生圖功能對口語講法沒反應

**現象**：使用者傳「生出一張你穿黑絲襪的圖給我」，機器人沒有生圖，直接掉進閒聊聊了起來。

**根因**：觸發判斷寫死成「必須用『畫』或『生圖』開頭」（`^(?:小蜜)?(?:畫|生圖)...`），「生出」不符合這個開頭，對不到規則。

**修法**：加一個口語意圖判斷（正則比對「畫/生成/生出」搭配「圖/圖片/照片」，不限位置），對到就把整句話直接當生圖描述丟進去，指令式「畫 XXX」寫法仍優先保留。

**驗收**：測「生一張你穿黑絲襪的圖給我」，這次確實觸發生圖流程（後續遇到 Gemini 生圖本身失敗，是另一個獨立問題——內容安全過濾疑慮，非觸發規則問題，當時加了除錯訊息但使用者後來沒有回報實際錯誤內容，此問題狀態未完全確認）。

## 問題 4：法規情境反查對「法律」講法沒反應

**現象**：使用者測「如果今天有人在公司對我口出惡言，我可以用哪一條法律告他」，機器人沒有走情境反查，而是被閒聊接走打哈哈帶過。

**根因**：觸發規則的關鍵字只認「法規」「法條」兩個詞（例如 `哪.{0,3}法(條|規)`），使用者講「法律」對不到。

**修法**：觸發規則的相關關鍵字全部加入「法律」，跟「法規」「法條」並列（`可以用.{0,5}(法條|法規|法律)`、`適用.{0,10}(法規|法條|法律)`、`哪.{0,3}法(條|規|律)`）。

**驗收提示**：貼上重新部署後，用「同事罵我可以用哪條法律告他」這類講法測試，應該會走情境反查而不是打哈哈。
